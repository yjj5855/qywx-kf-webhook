# 群公司档案写作规范（客服版）

> 本文档面向**写档案的客服人员**，说明群知识库里"群-公司档案"怎么填、填成什么样。
> 运维/技术细节见 `README.md` 的"群公司档案"一节与 `src/sync_company_profiles.py`。

## 1. 这份档案是干什么的

每个客服群在 Dify 里有一个自己的知识库，里面除每日聊天记录外，还有一份固定的
**「群-公司档案」**（文档名 `群档案_{群ID}`），内容是**本群对应客户公司的介绍**。
客服机器人回答"这家公司是谁""我们给这家公司做什么""这个群服务哪几家公司"之类问题时，
就是从这份档案里找答案。

**一个群可能对应多家公司**（例如"商图信息/柏奥会科技/滴图信息"是一个群、三家公司），
所以档案按"一家公司一块"来写。

## 2. 档案文件在哪、叫什么

- 位置：`docs/公司档案/` 目录
- 文件名：`{群ID}.md`，例如 `G0115.md`（群ID 就是群名前面的 G 编码）
- 一个文件 = 一个群的全部公司介绍；公司之间写在同一份文件里，用空行和标题隔开

## 3. 日常操作流程（三步）

```bash
# 第一步：生成模板（为已绑定公司ID、还没有档案的群生成 .md 文件）
python -m src.sync_company_profiles --init

# 第二步：用编辑器打开 docs/公司档案/{群ID}.md，按本规范填写各公司块

# 第三步：同步到知识库（把填写好的内容推送到 Dify 群知识库）
python -m src.sync_company_profiles
```

> 说明：`--init` 只生成模板，不同步；第三步是同步。每次改完档案都要重新跑第三步，
> 知识库里的文档才会更新（同步是"整篇替换"，不会出现新旧两份并存）。

## 4. 模板结构长什么样

模板由 `sync_company_profiles --init` 自动生成，结构如下（以三家公司为例）：

```markdown
本档案描述群 G0115（商图信息/柏奥会科技/滴图信息-小步人事服务群）对应的客户公司信息，供客服回答公司类问题时参考。

## 群信息
- 群ID：G0115
- 群名：商图信息/柏奥会科技/滴图信息-小步人事服务群
- 绑定公司数：3

## 公司清单
本群对应以下 3 家公司：

### 公司1：商图信息（公司ID：C2380）
商图信息是本群对应的客户公司，服务内容为（待填写：人事外包 / 社保公积金代缴 / 招聘 / 代发工资等）。
- 公司全称：（待填写，如"上海XX信息科技有限公司"）
- 常用称呼：（待填写，客户在群里怎么叫就写什么，如"商图"）
- 服务内容：（待填写，一句话说明为该客户提供哪些服务）
- 联系人/对接人：（待填写，可选；涉及个人隐私请谨慎）
- 备注：（待填写，账期、特殊约定等；敏感信息不写）

### 公司2：柏奥会科技（公司ID：KfdLmqbyBpqw3WwpRSNUZL）
……
```

## 5. 写作要求（务必逐条遵守）

### 5.1 每个公司块的第一句必须是完整句子
格式固定为：**`{公司称呼}是本群对应的客户公司，服务内容为……。`**
机器人是按"句子的意思"检索的，第一句是一句完整的自然语言，才能被"这家公司是干嘛的"
"我们给商图做什么"这类问题命中。**不要把第一句写成字段列表**。

### 5.2 全称、简称、别名都要写全
- 客户在群里怎么叫，就把它写进「常用称呼」（如"商图""柏奥"），可以写多个；
- 有公司全称的写「公司全称」；
- 群名里带的叫法和实际全称不一致时，两个都保留。
- 目的：客户用任何叫法提问，机器人都能对应到这家公司。

### 5.3 每块不要写太长
- 每家公司一块，控制在 **100～300 字** 左右；
- 块与块之间**必须用空行隔开**（知识库按空行分块，隔开才能保证一家公司一块，互不串）；
- 太长会被截断成多块，导致回答不完整；太短（只有一行）信息量不够。

### 5.4 多公司的固定规则
- 公司数量必须和「群信息」里的**绑定公司数一致**（模板生成时已按绑定顺序编号）；
- **不要改动公司编号、顺序和「## 群信息」里的内容**（群ID/群名/数量由系统生成）；
- 每家公司的信息写在自己的块里，**不要跨块混写**，不要新增"公司4"之类模板外编号；
- 如果某家公司名称是"（公司名称待填写）"，请把真实的客户叫法填上。

### 5.5 敏感信息不写
知识库内容机器人可以直接引用并发给客户，所以：
- ❌ 手机号、身份证号、工资、奖金、成本、内部折扣等一律**不写**；
- ❌ 客户的负面评价、催款、纠纷等内部信息**不写**；
- ✅ 只写"客户是谁、我们提供什么服务、服务上的约定"这类可对外口径的信息；
- 「联系人/对接人」可写可不写，写了也只写姓名/职务这类非敏感信息。

### 5.6 其他格式要求
- 用 Markdown 格式，标题层级照模板，不要发明新结构；
- **不要以单个 `#`（一级标题）开头**：Dify 解析文档时会剥掉行首的一级标题标记
  （`# xxx` 会变成 `xxx`，`##`/`###` 不受影响），文档名本身就是标题，正文第一行
  用模板开头的普通段落即可；
- 全角/半角括号、顿号不要混用（统一用模板里的样子）；
- 不确定的信息留 `（待填写）`，不要乱编。

## 6. 写完后自查清单

- [ ] 每家公司的块首句是"XX 是本群对应的客户公司，服务内容为……"的完整句子
- [ ] 常用称呼写的是客户在群里的真实叫法
- [ ] 公司数与绑定数一致，顺序没动
- [ ] 每块 100～300 字，块间有空行
- [ ] 没有手机号/身份证/工资等敏感信息
- [ ] 跑了 `python -m src.sync_company_profiles`，并提示该群"synced"

## 7. 常见问题

| 情况 | 怎么办 |
|---|---|
| 群还没绑定公司ID | `--init` 不会为它生成模板；先在群绑定里补公司ID，再重新 `--init` |
| 群里某家公司退出/新增 | 由管理员更新群绑定的公司ID；然后重新 `--init --force` 生成新模板，按新结构填写，再同步 |
| 群名里的公司名解析错了 | 正常现象，模板预填只是参考；直接改成正确的客户叫法即可 |
| 档案写错了/想清空 | 把文件内容清空（留空文件）再同步 = 从知识库移除该档案；文件整个删掉则需跑 `--prune` 清理残留 |
| 个人缴纳群 / 内部群 | 没有真实公司的，不填公司块，只在「公司清单」写一句"本群无绑定公司" |

## 8. 填写示例（好 vs 坏）

**✅ 好的写法：**

```markdown
### 公司1：商图信息（公司ID：C2380）
商图信息是本群对应的客户公司，服务内容为人事外包，主要为该公司员工提供入职、
合同与社保公积金代缴服务。
- 公司全称：商图信息
- 常用称呼：商图、商图信息
- 服务内容：人事外包、社保公积金代缴
- 联系人/对接人：王经理（人事部）
- 备注：每月 25 号前提交增减员名单
```

**❌ 坏的写法：**

```markdown
### 公司1：商图信息（公司ID：C2380）
服务：人事外包
客户联系人：王经理 138xxxxxxxx
本月应收 ¥12,000，账期 60 天，还在催款中
```

（字段堆砌、无首句、含手机号与内部经营信息，禁止这样写。）
